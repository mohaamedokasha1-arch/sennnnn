# أكاشا سينما (Akasha Cenima) — منصة عربية لاكتشاف الأفلام والمسلسلات

موقع **اكتشاف** وليس موقع مشاهدة: يعرض بيانات الأفلام والمسلسلات، مراجعات تحريرية أصلية،
تصنيفات، تريلرات رسمية (عند التصريح بتضمينها)، وروابط لمنصات مشاهدة **رسمية فقط**.

- **عربي بالكامل مع RTL** — واللون المميز والاسم والشعار كلها من ملف واحد: `site.config.mjs`،
  والهوية ثنائية اللغة: «أكاشا سينما» في الواجهة العربية و«Akasha Cenima» في الإنجليزية (LTR)
- **Next.js بخادم على Vercel** — المحتوى المنشور في `content/` متاح دائمًا كبديل للقراءة؛ لوحة التحكم تستخدم تخزينًا دائمًا (PostgreSQL عبر Neon/Vercel Postgres، أو Upstash Redis) عند تفعيله
- **لا API خارجي لجلب الأفلام** — البيانات الأصلية ملفات Markdown، والتعديلات الإدارية تُخزّن في PostgreSQL أو Redis أو ملف محلي أثناء التطوير
- **لا بيانات وهمية ولا أرقام مختلقة** — لا تقييمات مستخدمين ولا أعداد مشاهدات ولا إحصاءات غير موثّقة
- **لا تقييمات وهمية ولا أعداد مشاهدات مختلقة** — قسم «الأكثر مشاهدة» مخفي حتى تتوفر بيانات حقيقية

## أولًا: هيكل المشروع (الجذر نظيف — المهم أمامك مباشرة)

```
/  site.config.mjs     ← كل الهوية والإعدادات: الاسم (عربي/إنجليزي)، الشعار، اللون، البريد، المنصات المسموحة
   package.json        ← أوامر التشغيل (dev / build / start / validate)
   next.config.mjs     ← إعداد Next.js App Router لوضع الخادم على Vercel
   jsconfig.json       ← اختصار المسارات (@/ = جذر المشروع)
   README.md           ← هذا الملف: التشغيل والنشر
   CONTENT-GUIDE.md    ← دليل إضافة فيلم/مسلسل خطوة بخطوة (لغير المبرمجين)
   LEGAL.md            ← الالتزامات القانونية، وما لم يُنفَّذ في النسخة الأولى ولماذا
   ADS.md              ← إعلانات Adsterra: خريطة المواضع وطريقة التعديل من مكان مركزي واحد

   content/            ← المصدر الأصلي للمحتوى وبديل القراءة عند تعطل التخزين
     movies/           ← ملف لكل فيلم
     series/           ← ملف لكل مسلسل
     people/           ← ملف لكل مخرج/ممثل
     reviews/          ← ملف لكل مراجعة تحريرية
     lists/            ← ملف لكل قائمة ترشيحات
     _templates/       ← قوالب جاهزة للنسخ (لا تُقرأ في البناء)

   app/                ← الصفحات (هيكل Next.js القياسي، لا يمكن نقله)
   components/         ← مكوّنات الواجهة القابلة لإعادة الاستخدام
   lib/                ← منطق المشروع: قراءة المحتوى، التحقق، البحث، SEO، الأدوات
   public/             ← الصور والخطوط (posters/ · fonts/ · icons/)
   tools/              ← أدوات توليد البوسترات والأصول (تطوير فقط)
```

**مجلدان فرعيان لهما سبب تقني واضح:** `app/` لأن Next.js يفرضه، و`content/` لفصل المحتوى عن الكود
حتى يمكنك تحرير الأفلام دون لمس أي ملف برمجي.

## ثانيًا: التشغيل على جهازك (3 أوامر)

متطلبات مسبقة: تثبيت [Node.js](https://nodejs.org) نسخة 18 أو أحدث (الإصدار الموصى به: 20).

```bash
npm install          # 1) تنزيل المكتبات (مرة واحدة فقط)
npm run dev          # 2) تشغيل الموقع على جهازك → افتح http://localhost:3000
npm run build        # 3) بناء نسخة الخادم → تُنشئ مجلد .next/
npm run start        # معاينة نسخة الإنتاج محليًا
```

أوامر مفيدة أخرى:

| الأمر | ماذا يفعل؟ |
|---|---|
| `npm run validate` | يفحص ملفات المحتوى فقط ويكتشف الأخطاء (حقل ناقص، معرّف مكرر، صورة غير موجودة، رابط مشبوه) |
| `npm run test:content` | اختبارات الحالات الحدّية لمنظومة التحقق (تأكيد أن الحماية تعمل فعلًا) |
| `npm run test:logic` | اختبارات منطق البحث والفلاتر والترتيب والترقيم والاقتراحات |
| `npm run test:storage` | اختبارات التخزين المحلي وRedis بمحاكاة، وتعطل المخزن وبديل المحتوى |
| `npm run test:storage:pg` | اختبارات محرّك PostgreSQL (Neon/Vercel Postgres) بتنفيذ SQL فعلي عبر PGlite: تطبيع الروابط وsslmode تلقائي، مزامنة السكيما، CAS، وفشل مغلق |
| `npm run test:seo` | اختبارات انحدار لاسم العلامة والاتجاه وعناوين/أوصاف SEO وصور المشاركة المحلية |
| `npm run test:analytics` | يفحص Google Tag ومعرّف القياس وتهيئة dataLayer دون اتصال بخدمة Google |
| `npm test` | يشغّل التحقق واختبارات المحتوى والمنطق والتخزين وSEO والبوسترات والإعلانات والتحليلات (شغّله قبل أي نشر) |
| `npm run clean` | حذف مخرجات البناء (`.next` و`out`) |

> ملاحظة: أمر `prebuild` تلقائي: كل بناء يشغّل `validate` أولًا. **إذا توجد أخطاء في المحتوى، يتوقف
> البناء ولا يُنشر الموقع** — هذا مقصود: لا ننشر بيانات ناقصة.

**عرض الموقع العام لا يحتاج متغيرات بيئة.** لتفعيل لوحة التحكم على Vercel، الطريقة الموصى بها: اضبط `DATABASE_URL` برابط PostgreSQL (Neon / Vercel Postgres) — تُزامَن السكيما تلقائيًا ويُضاف `sslmode=require` إن غاب. البديل: ربط Redis REST بزوج المتغيرات في `.env.example` / إعدادات Vercel. لا توجد كلمة مرور افتراضية. راجع [دليل لوحة التحكم](ADMIN-SETUP.md).

## ثالثًا: النشر على Vercel (الخطة المجانية)

للموقع العام، لا تحتاج إلى قاعدة بيانات. للوحة التحكم وتعديلات الأفلام الدائمة، يلزم مخزن دائم (PostgreSQL عبر `DATABASE_URL` — موصى به — أو Redis REST)؛ نظام ملفات Vercel ليس مخزنًا دائمًا:

**الطريقة الأسهل (بدون سطر أوامر):**
1. أنشئ مستودعًا على GitHub وارفع المشروع إليه (`git init` ثم `git add .` ثم `git commit` ثم `git push`).
2. ادخل إلى [vercel.com](https://vercel.com) → **Add New → Project** → اختر المستودع.
3. اختر Framework = **Next.js** وBuild Command = `npm run build` واترك Output Directory فارغًا. لا تضبط `AKASHA_STATIC_EXPORT=1` للإنتاج. لتفعيل الإدارة أضف `DATABASE_URL` برابط Neon / Vercel Postgres (تُنشأ الجداول تلقائيًا عند أول زيارة لـ `/admin/setup/`)، أو `UPSTASH_REDIS_REST_URL` و`UPSTASH_REDIS_REST_TOKEN` من تكامل Upstash، ثم أعد النشر.
4. بعد أول نشر: افتح `site.config.mjs` واستبدل `url` بالنطاق الحقيقي، ثم عدّل البريد، ثم `git push` مرة أخرى.

**الطريقة البديلة (سطر أوامر):** `npm i -g vercel` ثم `vercel` واتبع التعليمات.

**بعد النشر — تحقق من هذه النقاط:**
- `/sitemap.xml` و`/robots.txt` يظهران وبهما نطاقك الصحيح.
- شغّل `npm run seo:live` من اتصال خارجي: يطلب `robots.txt` و`sitemap.xml` بهوية User-Agent تحاكي Googlebot، ثم يفحص HTTP 200 وMIME type وكل صفحة مدرجة (200 + canonical ذاتي + بلا `noindex`).
- اختبر `/movies/` و`/series/` و`/genres/drama/` وصفحة فيلم ومسلسل و`/admin/setup/` وشريط البحث على الهاتف. بدون مخزن دائم تظهر في الإدارة رسالة إعداد واضحة بدل خطأ 500، وتبقى المكتبة العامة متاحة.
- في Google Search Console: أضف النطاق وارفع الرابط الكامل `https://<نطاقك>/sitemap.xml` — ووسم الإثبات `google-site-verification`
  مُدرج مسبقًا في `<head>` لكل الصفحات من `site.config.mjs` (تأكد من مطابقة الرمز لرمزك قبل الضغط على «تحقق»).
- إذا بقي Search Console عالقًا على «تعذرت قراءة خريطة الموقع» رغم أن الملف سليم (نتيجة فاشلة قديمة محفوظة لديه)،
  جرّب `https://<نطاقك>/sitemap-all.xml`؛ مرآة مطابقة لخريطة الموقع الحيّة تُولَّد عند الطلب.

**تحديث المحتوى:** عدّل ملفًا في `content/` → احفظ → `git push` → Vercel يعيد النشر تلقائيًا في دقائق.
(لا تحتاج أي خطوة يدوية أخرى، ولا تنسَ أن أي تغيير في البيانات يمرّ على `npm run validate` أولًا.)

## رابعًا: كيف تُبنى الصفحات؟ (شرح مبسّط)

1. تشغيل التحقق: يقرأ `content/**` ويرفض أي حقل إلزامي ناقص أو معرّف مكرر أو رابط غير مسموح.
2. البناء: يتحقق من Markdown ويجهّز صفحات Next.js. تُقرأ بيانات الأفلام وقت الطلب؛ فهرس البحث وخريطة الموقع يتحدثان مع البيانات المنشورة.
3. النشر: تعمل الصفحات عبر Next.js App Router؛ فشل التخزين يعيد المكتبة إلى نسخة Markdown المحفوظة بدل انهيار الموقع. وظائف الإدارة تحتاج مخزنًا دائمًا (PostgreSQL أو Redis).

## سادسًا: الميزات المنفَّذة فعليًا (بلا API خارجي)

- **البحث الداخلي:** بحث جزئي بالعربية أو بالاسم الأصلي، مع تطبيع الهمزات والتاء المربوطة («الاخيره» = «الأخيرة»)،
  اقتراحات فورية في الشريط العلوي، وصفحة نتائج كاملة.
- **الفلاتر والترتيب:** النوع، السنة، اللغة، البلد، (وحالة المسلسل) + ترتيب بالاسم/السنة/أحدث إضافة.
- **الترقيم:** 24 عنصرًا لكل صفحة بحد أقصى (لا تحميل كامل للبيانات دفعة واحدة).
- **أفلام/مسلسلات مشابهة:** تُحسب من تقاطع التصنيفات داخل بيانات الموقع فقط.
- **المفضلة:** تُحفظ في `localStorage` (اسم المفتاح: `cinemana:favorites`) — مع إشعار صريح للزائر
  أنها لا تنتقل بين الأجهزة وتُفقد عند مسح بيانات المتصفح.
- **المشاركة:** نسخ رابط الصفحة + روابط مباشرة (X / واتساب)، وكل رابط صفحة قابل للمشاركة.
- **روابط داخلية غنية:** كل عمل ↔ تصنيفاته ↔ ممثلوه/مخرجوه ↔ مراجعته ↔ قوائمه.

## سابعًا: SEO المطبَّق

- لكل صفحة قابلة للفهرسة عنوان فريد بطول 50–60 حرفًا ووصف فريد بطول 150–160 حرفًا، و`Canonical` ذاتي صحيح؛ يفحص البناء 419 عنوانًا/وصفًا.
- `sitemap.xml` و`robots.txt` **مُولَّدان تلقائيًا** من بيانات المحتوى الفعلية، بما فيها صفحات `/movies/page/<n>/` و`/series/page/<n>/`؛ مرآة `sitemap-all.xml` مطابقة بايتًا ببايت لتسهيل الإرسال إلى Search Console.
- يضبط `vercel.json` تحويلات دائمة للمسارات المفردة/الجمع القديمة نحو النسخة canonical، ورأس `X-Robots-Tag` لفهرس البحث وملف manifest.
- يتضمن التصدير 67 زوجًا عربيًا/إنجليزيًا لصفحات الأفلام مع `hreflang` متبادل (`ar`/`en`/`x-default`). النسخة الإنجليزية الحالية لصفحات التفاصيل فقط، ولا توجد صفحة رئيسية أو مكتبة إنجليزية كاملة.
- Schema.org المنشور حاليًا: `Movie` / `TVSeries` / `Person` / `BreadcrumbList` / `WebSite` / `Organization`; تُبنى البيانات فقط من الحقول الفعلية، بلا `aggregateRating` مختلق.
- `noindex` لصفحات البحث والمفضلة والأقسام الفارغة (المراجعات والقوائم عند عدم وجود محتوى) وصفحة 404.
- Open Graph وTwitter Card: بوستر العمل أولًا، ثم صورة افتراضية محلية عربية `public/og-default.jpg` أو إنجليزية `public/og-default-en.jpg`، وكلتاهما 1200×630.
- H1 واحد لكل صفحة، وتسلسل عناوين منطقي، ونصوص `alt` وصفية للبوسترات. تدقيق التصدير يفحص 558 صفحة HTML وروابطها/صورها المحلية.
- أيقونات PWA: ملف manifest عربي أساسي مع PNG بقياسي 192 و512 بكسل، وfavicon متعدد الأحجام (16/32/48/64) وأيقونة Apple 180×180.
- وسم إثبات الملكية لـ**Google Search Console** (`google-site-verification`) يُدرج في `<head>` لكل صفحة ويُضبط من `site.config.mjs` ← `googleSiteVerification`. فحص البناء يتحقق من وجود القيمة ومطابقتها في التصدير فقط؛ لا يثبت ملكية الموقع داخل Search Console ولا يرسل طلب فهرسة.

## ثامنًا: الأداء والوصولية والأمان

- العرض العام يعمل دون قاعدة بيانات عند غياب إعداد التخزين؛ يُستخدم كاش قصير لقراءات المخزن عند تفعيله.
- البوسترات 600×900؛ يدقق البناء أن كل صورة محلية لا تتجاوز 200 KiB، ويطبق **تحميلًا كسولًا** لما هو خارج الشاشة الأولى. الأغلفة التصميمية موسومة صراحة بأنها أصلية وليست بوسترات رسمية.
- خط عربي واحد (IBM Plex Sans Arabic) مستضاف محليًا: **4 ملفات woff2 بحجم إجمالي ~92KB**، بلا CDN خارجي.
- تقرير `next build` الأخير يعرض 103 KB للـJavaScript المشترك و114–120 KB لـFirst Load JS بحسب المسار. فحص حجم البناء ليس بديلًا عن Lighthouse أو Core Web Vitals على النطاق المنشور.
- الحد الأدنى من المكتبات: `next`، `react`، `gray-matter`، `js-yaml`، `marked` — لا مكتبات واجهة ثقيلة.
- RTL كامل، تباين ألوان كافٍ، تنقل كامل بلوحة المفاتيح، `skip-link`، وسم `lang`/`dir` صحيح،
  واحترام `prefers-reduced-motion`.
- لا شاشة بيضاء عند الخطأ: صفحة `error.jsx` عربية وودّية، وصفحة 404 مفيدة.
- لا أسرار في الكود. روابط/رموز قواعد البيانات (PostgreSQL أو Redis) تُضبط فقط في متغيرات البيئة ولا تُرفع إلى Git، ولا تُطبع في السجلات.

## تاسعًا: الإعلانات (Adsterra) — مفعّلة من مكان مركزي واحد

كل وحدات Adsterra مفعّلة من **مكان واحد فقط**: `site.config.mjs` ← `ads` (Popunder، Social Bar،
Smartlink، Native Banner، و6 بانرات). لا يُلصق أي كود داخل الصفحات أو القوالب.

- Popunder داخل `<head>` وSocial Bar قبل `</body>` في التخطيط الجذري (كل الصفحات، مرة واحدة).
- 728×90 تحت الهيدر، وعمودان جانبيان 160×600/160×300 على الشاشات العريضة.
- صفحات الأفلام والمسلسلات (قالب واحد ⇐ كل عمل جديد تلقائيًا): 320×50 أعلى المشغّل (موبايل)، 300×250
  بجانبه، 468×60 أسفل روابط المشاهدة، Native تحت الأعمال المشابهة، وزرّا Smartlink بشارة «إعلان».
- كل كود يظهر **مرة واحدة فقط** في الصفحة (شرط Adsterra)، وكل بانر في إطار مستقل بلا مشكلات Hydration
  وبمقاس محجوز (لا قفز في الصفحة)، وتحميل كسول، وطيّ تلقائي عند حجب الإعلانات.
- الإعلانات الحقيقية على نطاق الإنتاج فقط؛ محليًا وفي معاينات Vercel تظهر مربعات توضيحية بلا أي طلب لـ Adsterra.

خريطة المواضع الكاملة وطريقة التعديل/الإيقاف: `ADS.md` · الاختبارات: `npm run test:ads`.

## أحد عشر: الأسئلة السريعة

- **كيف أغيّر اسم الموقع أو لونه؟** من `site.config.mjs` (`nameByLocale` و`shortNameByLocale` و`logo` واللون)، وتقرأ الواجهة ذلك عبر `lib/brand.mjs` دون تكرار الاسم في المكوّنات.
- **كيف أضيف فيلمًا؟** راجع `CONTENT-GUIDE.md` (خطوات مفصّلة لغير المبرمج).
- **كيف أُخفي عملًا دون حذفه؟** اجعل `draft: true` في ملفه، ثم أعد النشر.
- **ما المتوفر بالإنجليزية؟** توجد حاليًا صفحات تفاصيل إنجليزية للأفلام المنشورة التي لها `synopsisEn` (`/en/movies/<slug>/`؛ والمسار المفرد alias قديم). الصفحة الرئيسية والتنقل الكامل ما زالا بالعربية.
- **ما الذي يمنع نشر رابط قرصنة بالخطأ؟** التحقق عند البناء يرفض أي رابط مشاهدة على نطاق غير مدرج في
  قائمة المنصات الرسمية، ويرفض أي صورة بوستر من نطاق خارجي.


## Google Analytics 4

- Google Tag بالمعرّف `G-MTEY12JS7Q` موجود مرة واحدة في `app/layout.jsx` ويشمل الصفحات العربية والإنجليزية.
- يستخدم `next/script` مع `strategy="afterInteractive"`؛ لا ينفّذ أي وصول إلى `window` أثناء التصيير على الخادم، ويحتفظ بأي `dataLayer` موجودة.
- لا حاجة إلى متغيرات بيئة أو حزمة إضافية. لا تضف نسخة أخرى من الوسم عبر GTM لتجنب تكرار الأحداث.
- لتسجيل التنقلات الداخلية في App Router، تأكد من تفعيل **Enhanced measurement → Page views → Page changes based on browser history events** في تدفق بيانات GA4. لا نضيف أحداث `page_view` يدوية حتى لا تتكرر مع القياس المحسّن.

### التحقق بعد النشر على Vercel

1. انشر التغييرات على نطاق الإنتاج `https://akasha-cenima.vercel.app/`، ثم افتحه في متصفح لا يحظر أدوات التحليل.
2. في أدوات المطور، تحقق من تحميل `gtag/js?id=G-MTEY12JS7Q` ومن طلبات `g/collect` الخاصة بالمعرّف نفسه؛ تحقق أيضًا من `window.dataLayer` وعدم وجود أخطاء Hydration في Console.
3. افتح صفحة عربية وصفحة إنجليزية وتنقّل بينهما؛ راقب الزيارات في **Realtime** (أو **DebugView** عند تفعيل وضع التصحيح).
4. استخدم **Test your website** في إعداد Google Tag بعد اكتمال النشر. لا يمكن تأكيد نتيجة الفحص أو وصول الأحداث بمجرد نجاح البناء؛ الحظر وإعدادات GA4 وتأخر معالجة البيانات قد تؤثر على النتيجة.

> تنبيه: هذا الدمج لا يضيف منصة موافقة أو Consent Mode. على إدارة الموقع مراجعة متطلبات موافقة الزوار حسب المناطق المستهدفة، وإضافة إدارة موافقة قبل تشغيل التحليلات حيث تكون مطلوبة. تم تحديث صفحتي الخصوصية وملفات تعريف الارتباط للإفصاح عن GA4.
